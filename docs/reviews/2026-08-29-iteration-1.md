## B1 — blocking — auto-merge with no CI evidence; CI-evidence gate is dead code
`src/pipeline/github_client.py:301-326, 551-558` (+ `__main__.py:391-588`)

pass the result into `publish_artifacts` as a required `ci_green` argument defaulting to `False`;

## B2 — blocking — issue→PR ordering not durably recorded; replay duplicates the issue
`src/pipeline/__main__.py:119-212` (+ `state.py:70-99`, `github_client.py:532-559`)
Plan: §14.1 lifecycle issue → PR → issue-patch with the state row advanced **per artifact**,
marker search over existing issues/PRs, crash recovery resuming from the last recorded state,
including the explicit "issue created but PR failed" replay case.
Code: `_publish_live` appends one `DISPATCHING` row (132-135); `ISSUE_CREATED` / `PR_CREATED` rows
carrying `issue_url` / `pr_url` exist only in memory (158-165, 203-211) and reach disk at the end
of `run_once`. `existing_artifact` looks for urls/states never written, and its `marker_exists`
fallback scans local checkout files (`state.py:13-30`), which never contain an artifact marker.
GitHub is never queried.
Trigger: LIVE, `create_issue` succeeds and `create_pr` fails (422 "No commits between …" is the
ordinary case given M3, or a 5xx) → `RunAbort`, durable state says only `dispatching`. Re-running
opens a SECOND issue for the same `candidate_id`; each retry adds one.
Fix: append a state row after every individual write (issue → `ISSUE_CREATED`, PR →
`PR_CREATED`, patch → patched); make the dedupe check resume-aware so a row with `issue_url` and
no `pr_url` skips `create_issue` and resumes at the PR write with the recorded issue number;
implement `marker_exists` against the GitHub search/issue listing API.

## M2 — major — red baseline is never executed; SIMULATE fabricates a valid one
`src/pipeline/session_client.py:279-302` (+ `review_loop.review_iteration_from_payload`,

## M3 — major — no per-candidate branch: every PR opened from one CLI-supplied head
`src/pipeline/__main__.py:414-415, 187, 198, 567-577`
